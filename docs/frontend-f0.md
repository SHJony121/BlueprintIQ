**Scope:** `frontend/` scaffold, strict TypeScript, Tailwind, lint, build, CI, and a minimal PDF.js worker compatibility check. No viewer, proxy or inspection UI yet.

## Deliberate changes to the scaffold

* Removed the template's experimental `cacheComponents` and `partialPrefetching` (extra caching semantics a client-heavy, proxy-backed single screen does not need) and `poweredByHeader`.
* Local `geist` fonts instead of `next/font/google`, so builds are reproducible offline.
* `AGENTS.md` is generated by Next (it points tooling at the docs shipped in `node_modules/next/dist/docs`); kept as the generator intends.

## PDF.js worker check (verified in a real browser)

`src/lib/pdfjs.ts` loads PDF.js lazily and sets `GlobalWorkerOptions.workerSrc = new URL("pdfjs-dist/build/pdf.worker.min.mjs", import.meta.url)`. Turbopack emits the worker as a static asset (`/_next/static/media/pdf.worker.min.*.mjs`), so nothing is fetched from a CDN.

`/pdfjs-check` loads a synthetic fixture (`valid_basic.pdf`), parses it, and prints the result. Observed on both the **production build** (`next start`) and the **dev server**:

```
ok pdfjs=6.4.299 pages=1 size=595x842 text=THICKNESS: 4 mm DIAMETER: 20 mm LENGTH: 120 mm MATERIAL: SS400 TITLE: BRACKET SCALE: 1:2 DRAWN: SYNTHETIC FIXTURE
```

with no console errors. The page size matches the backend's `width_pt` x `height_pt` for that fixture (595 x 842). Not yet verified: rendering to a canvas, rotated/cropped pages, and overlay alignment (F3).

## Checks and CI

`npm run check` = ESLint, `next typegen && tsc --noEmit`, `next build`. (`LayoutProps` and route types are generated by Next, so `typegen` must precede `tsc` on a fresh checkout; a clean-tree run caught this.) The `frontend-ci` workflow runs `npm ci`, lint, typecheck, build and `npm audit --omit=dev --audit-level=high`.

**Audit note.** `npm audit` (including dev dependencies) reports 5 high advisories, all one chain: `braces` → `micromatch` → `fast-glob` → `@next/eslint-plugin-next` → `eslint-config-next`. It is a dev-only lint dependency (regular-expression denial of service on crafted glob patterns) and is never part of the build output. The suggested `npm audit fix --force` would *downgrade* `eslint-config-next` to 14.x, which is incompatible with Next 16, so it is not applied. Production dependencies report 0 vulnerabilities, and CI gates on that.
